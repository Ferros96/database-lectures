62153 · Intro to Database Systems · Lecture 4 · Part 303 / 28
01 · Update operations

Three operations change the state

The operations of the relational model can be categorized into retrievals and updates. Three basic operations change the states of relations (tables):

Insert

01

Insert new data: add a new tuple (row) to a relation.

Delete

02

Delete old data: remove one or more tuples.

Update (Modify)

03

Modify existing data: change attribute (column) values of existing tuples.

Whenever these operations are applied, the integrity constraints specified on the relational database schema should not be violated.
⏱ 2 min
Goal

Name the three operations.

Say

Insert adds a tuple, delete removes tuples, update changes values in tuples that already exist. After any of them, the database state must still satisfy every constraint.

How to explain it

Link to Part 2: a database state is only valid if it satisfies IC. An update operation moves the database from one state to the next, and the new state must be valid too.

Example to use

Hiring an employee is an insert. An employee leaving is a delete. A pay rise is an update.

Watch out for

‘Update’ is used two ways: for all three operations together, and for the Modify operation alone. Say which one you mean.

⏱ 3 min
Goal

The one slide to remember from today.

Say

Insert can break all four constraints, because a brand-new tuple brings brand-new values. Delete can only break referential integrity: removing a tuple can leave other tuples pointing at nothing. Update depends on what you change.

How to explain it

Explain delete by elimination: deleting cannot create a bad value, a duplicate key or a NULL key, because it adds nothing. The only thing it can break is a reference to the deleted tuple.

Ask the class

Which operation did you guess was the most dangerous at the start? Was it right?

Watch out for

The update row comes from the textbook: changing an ordinary attribute can only break the domain constraint; changing a key or foreign key can break more.

62153 · Intro to Database Systems · Lecture 4 · Part 306 / 28
02 · The Insert operation

Insert can violate all four constraints

Insert provides a list of attribute (column) values for a new tuple (row) t that is to be inserted into a relation (table).

Domain (allowed values)

An attribute value does not appear in the corresponding domain or is not of the appropriate data type.

Key

A key value in the new tuple t already exists in another tuple in the relation.

Entity integrity

Any part of the primary key of the new tuple t is NULL.

Referential integrity

The value of any foreign key in t refers to a tuple that does not exist in the referenced relation.

⏱ 2 min
Goal

Turn the four constraints into four checks.

Say

For every new tuple the DBMS asks four questions: is each value in its domain? Is the key new? Is the primary key filled in? Does every foreign key point to an existing tuple?

How to explain it

Write the four questions on the board as a checklist. Students will use it on the next four slides.

Transition

Now four inserts from the lecture. Predict before I reveal.

62153 · Intro to Database Systems · Lecture 4 · Part 313 / 28
03 · The Delete operation

Delete can violate only referential integrity

Only referential integrity

The Delete operation can violate only referential integrity.

When it happens

This occurs if the tuple (row) being deleted is referenced by foreign keys from other tuples in the database.

How a delete is specified

A condition on the attributes (columns) of the relation (table) selects the tuple (or tuples) to be deleted.

⏱ 2 min
Goal

One rule for delete.

Say

Before deleting a tuple, the DBMS asks one question: does anyone point at this tuple? If yes, the delete would leave a broken reference.

How to explain it

Use the Part 2 slide of all foreign keys in COMPANY: to check a delete on EMPLOYEE, look at every arrow that ends at EMPLOYEE.Ssn.

Example to use

Deleting a department that still has employees would leave those employees with a Dno that points nowhere.

62153 · Intro to Database Systems · Lecture 4 · Part 319 / 28
04 · The Update operation

The Update (Modify) operation

What it does

Changes the values of one or more attributes (columns) in a tuple (or tuples (rows)) of some relation (table) R.

Selecting the tuples

A condition on the attributes of the relation selects the tuple (or tuples) to be modified.

Ordinary attribute

Changing an attribute that is neither a primary key nor a foreign key can only violate its domain (allowed values).

Key or foreign key

Changing a primary key or a foreign key needs the same checks as an insert, plus a delete check for the old key value.

⏱ 2 min
Goal

Know what to check for an update.

Say

First ask: which attribute is changing? A salary: only check its domain. A foreign key: check it points to an existing tuple. A primary key: check it is unique and not NULL, and check nobody was pointing at the old value.

How to explain it

The last two cards come from the textbook. Explain that changing a primary key is like deleting the old tuple and inserting a new one.

Transition

Goal

Changing a primary key: two violations at once.

Say

Changing a primary key is the riskiest update: the new value must be unique, and nobody may still be using the old one.

How to explain it

Do it in two steps. Step 1, like an insert: is 987654321 already used? Yes, by Jennifer, so key violation. Step 2, like a delete: who pointed at 999887777? Her WORKS_ON tuples, so referential integrity is violated too.

Watch out for

Students usually find only the first violation. Ask ‘and who was pointing at the old value?’

62153 · Intro to Database Systems · Lecture 4 · Part 326 / 28
05 · Handling a violation

Ways to enforce the constraints

When an operation would violate a constraint, the DBMS (or the user) can respond in several ways (Elmasri & Navathe, Section 5.3):

Reject (restrict)

Refuse the operation and explain why. This is the default.

Cascade

Also delete or update the tuples (rows) that reference the one being deleted or changed.

Set NULL / default

Set the referencing foreign keys to NULL or a default value (not allowed if the FK is part of a primary key).

Correct it

Ask the user to fix the operation, e.g. insert the missing DEPARTMENT 7 first.

⏱ 3 min
Goal

Know the four responses.

Say

Reject is the safe default. Cascade passes the delete on to the referencing tuples. Set NULL keeps those tuples but empties their reference. Or the user corrects the data first.

How to explain it

Apply each option to delete example 2, deleting Alicia. Reject: refused. Cascade: her WORKS_ON tuples are deleted too. Set NULL: impossible, because WORKS_ON.Essn is part of the primary key. Correct: reassign her projects first.

Watch out for

Set NULL cannot be used when the foreign key is part of the primary key, as in WORKS_ON. That is entity integrity again.

Key takeaways

  1. 01

    Three basic operations change a database state: Insert, Delete and Update (Modify).

  2. 02

    Insert can violate all four constraints: domain (allowed values), key, entity integrity and referential integrity.

  3. 03

    Delete can violate only referential integrity, when other tuples (rows) reference the deleted tuple.

  4. 04

    Update can violate any constraint, depending on whether an ordinary attribute (column), a foreign key or a primary key is changed.

  5. 05

    A violation can be handled by rejecting, cascading, setting NULL or a default, or correcting the data.
