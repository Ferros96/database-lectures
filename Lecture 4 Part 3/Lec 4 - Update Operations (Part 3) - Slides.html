62153 · Intro to Database Systems · Lecture 4 · Part 303 / 31
01 · Update operations

Update operations

From the lecture · Lecture 4 · Part 3
  • The operations of the relational model can be categorized into retrievals and updates.
  • There are three basic operations that can change the states of relations (tables) in the database:
    • Insert to insert new data.
    • Delete to delete old data.
    • Update (or Modify) to modify existing data records.
  • Whenever these operations are applied, the integrity constraints specified on the relational database schema should not be violated.
In plain words

Retrievals only read data. Insert, delete and update change it, and every change is checked: after the operation, the database state must still satisfy all the constraints from Part 2 (domain (allowed values), key, entity integrity, referential integrity).

Hiring an employee = insert · an employee leaves = delete · a pay rise = update.

⏱ 3 min
Goal

Teach the lecture’s definition of update operations.

Say

Read the first bullet: operations are either retrievals, which only read, or updates, which change the data. Then the three operations: insert adds new data, delete removes old data, update or modify changes existing records. Last bullet: whatever we do, the integrity constraints must not be violated.

How to explain it

Link to Part 2: a database state is valid only if it satisfies IC. Each operation moves the database from one state to the next, and the new state must also be valid.

Example to use

Hiring an employee is an insert. An employee leaving is a delete. A pay rise is an update.

Watch out for

‘Update’ is used two ways: for all three operations together, and for the Modify operation alone. Say which one you mean.

⏱ 3 min

The one slide to remember from today.

Say

Insert can break all four constraints, because a brand-new tuple brings brand-new values. Delete can only break referential integrity: removing a tuple can leave other tuples pointing at nothing. Update depends on what you change.

How to explain it

Explain delete by elimination: deleting cannot create a bad value, a duplicate key or a NULL key, because it adds nothing. The only thing it can break is a reference to the deleted tuple.

Watch out for

The update row comes from the textbook: changing an ordinary attribute can only break the domain constraint; changing a key or foreign key can break more.

62153 · Intro to Database Systems · Lecture 4 · Part 306 / 31
02 · The Insert operation

The Insert operation

From the lecture · Lecture 4 · Part 3
  • The insert operation provides a list of attribute (column) values for a new tuple (row) t that is to be inserted into a relation (table).
    • Domain constraints can be violated if an attribute value is given that does not appear in the corresponding domain (allowed values) or is not of the appropriate data type.
    • Key constraints can be violated if a key value in the new tuple t already exists in another tuple in the relation.
    • Entity integrity can be violated if any part of the primary key of the new tuple t is NULL.
    • Referential integrity can be violated if the value of any foreign key in t refers to a tuple that does not exist in the referenced relation.
In plain words

Insert can violate all four constraints. For each new tuple the DBMS asks four questions: Is every value in its domain? Is the key value new? Is the primary key filled in (no NULL)? Does every foreign key point to an existing tuple?

⏱ 3 min
Goal

Turn the four constraints into four checks.

Say

Read the four sub-bullets: an insert can break the domain, key, entity integrity or referential integrity constraint. Each one is a different mistake in the new tuple.

How to explain it

Write the four questions from the ‘In plain words’ box on the board as a checklist. Students use it on the next four slides.

⏱ 30 s

62153 · Intro to Database Systems · Lecture 4 · Part 313 / 31
03 · The Delete operation

The Delete operation

From the lecture · Lecture 4 · Part 3
  • The Delete operation can violate only referential integrity.
  • This occurs if the tuple (row) being deleted is referenced by foreign keys from other tuples in the database.
  • To specify deletion, a condition on the attributes (columns) of the relation (table) selects the tuple (or tuples) to be deleted.
In plain words

Deleting adds no values, so it cannot create a bad value, a duplicate key or a NULL key. The only thing it can break is a reference: if other tuples point at the deleted tuple, they are left pointing at nothing.

Check a delete by asking: who points at this tuple? Follow every foreign key arrow that ends at this relation.

⏱ 3 min
Goal

One rule for delete.

Say

Read the three bullets. Delete can violate only referential integrity, and only when the deleted tuple is referenced by foreign keys. The tuples to delete are chosen by a condition, for example Ssn = '999887777'.

How to explain it

Explain ‘only referential integrity’ by elimination: deleting adds nothing, so domain, key and entity integrity can’t break. Use the Part 2 slide of all foreign keys in COMPANY to see which arrows end at a relation.

Example to use

Deleting a department that still has employees would leave those employees with a Dno that points nowhere.

Changing attribute (column) values

⏱ 30 s

Say

Update, or modify, changes values in existing tuples. What it can break depends on which attribute we change.

62153 · Intro to Database Systems · Lecture 4 · Part 319 / 31
04 · The Update operation

The Update operation

From the lecture · Lecture 4 · Part 3
  • The Update (or Modify) operation is used to change the values of one or more attributes (columns) in a tuple (or tuples (rows)) of some relation (table) R.
  • It is necessary to specify a condition on the attributes of the relation to select the tuple (or tuples) to be modified.
In plain words

What an update can violate depends on which attribute changes. An ordinary attribute (e.g. Salary): only its domain (allowed values). A foreign key (e.g. Dno): it must still point to an existing tuple. A primary key (e.g. Ssn): it must stay unique and not NULL, and no tuple may still refer to the old value.

Changing a primary key works like deleting the old tuple and inserting a new one, so both sets of checks apply (textbook, Section 5.3).

⏱ 3 min
Goal

Know what to check for an update.

Say

Read the two bullets: update changes attribute values in existing tuples, and a condition selects which tuples. Then the key question: which attribute is changing?

How to explain it

Use the plain-words box: ordinary attribute, foreign key or primary key, and the checks for each. The primary key case is the hardest; it is the last example.

Goal

Changing a primary key: two violations at once.

Say

Changing a primary key is the riskiest update: the new value must be unique, and nobody may still be using the old one.

How to explain it

Watch out for

Students usually find only the first violation. Ask ‘and who was pointing at the old value?’

62153 · Intro to Database Systems · Lecture 4 · Part 326 / 31
05 · Handling a violation

Ways to enforce the constraints

When an operation would violate a constraint, the DBMS (or the user) can respond in several ways (Elmasri & Navathe, Section 5.3):

Reject (restrict)

Refuse the operation and explain why. This is the default.

Cascade

Also delete or update the tuples (rows) that reference the one being deleted or changed.

Set NULL / default

Set the referencing foreign keys to NULL or a default value (not allowed if the FK is part of a primary key).

Correct it

Ask the user to fix the operation, e.g. insert the missing DEPARTMENT 7 first.

⏱ 3 min
Goal

Know the four responses.

Say

Reject is the safe default. Cascade passes the delete on to the referencing tuples. Set NULL keeps those tuples but empties their reference. Or the user corrects the data first.

How to explain it

Apply each option to delete example 2, deleting Alicia. Reject: refused. Cascade: her WORKS_ON tuples are deleted too. Set NULL: impossible, because WORKS_ON.Essn is part of the primary key. Correct: reassign her projects first.

Watch out for

Set NULL cannot be used when the foreign key is part of the primary key, as in WORKS_ON. That is entity integrity again.

Foreign keys: ORDER.Cust# → CUSTOMER, ORDER_ITEM.Order# → ORDER, ORDER_ITEM.Item# → ITEM, SHIPMENT.Order# → ORDER, SHIPMENT.Warehouse# → WAREHOUSE. Other constraints: Qty > 0, Ship_date ≥ Odate, Ord_amt = sum of Qty × Unit_price.

Watch out for

Because an order can ship from several warehouses, SHIPMENT’s key must include both Order# and Warehouse#.

Key takeaways

  1. 01

    Three basic operations change a database state: Insert, Delete and Update (Modify).

  2. 02

    Insert can violate all four constraints: domain (allowed values), key, entity integrity and referential integrity.

  3. 03

    Delete can violate only referential integrity, when other tuples (rows) reference the deleted tuple.

  4. 04

    Update can violate any constraint, depending on whether an ordinary attribute (column), a foreign key or a primary key is changed.

  5. 05

    A violation can be handled by rejecting, cascading, setting NULL or a default, or correcting the data.
