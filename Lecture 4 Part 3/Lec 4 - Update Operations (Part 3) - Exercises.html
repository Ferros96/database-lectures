A · Concepts

Pick the best answer. You get feedback straight away.

Q1
Which three basic operations change the state of a relation (table)?
Insert, Delete and Update (Modify) change the state; retrievals only read it.
Q2
Which constraint is the only one a Delete can violate?
Deleting adds no values, so only a reference to the deleted tuple (row) can break.
Q3
An Insert gives a value that is not of the attribute (column)’s data type. Which constraint is violated?
Values must come from the attribute (column)’s domain (allowed values) and be of the appropriate data type.
Q4
An Insert has NULL for part of the primary key. Which constraint is violated?
Entity integrity: no part of a primary key can be NULL.
Q5
How does the DBMS know which tuples (rows) a Delete or Update applies to?
A condition on the attributes (columns) of the relation (table) selects the tuple (or tuples (rows)).
Q6
Updating which kind of attribute (column) can violate only the domain constraint?
An ordinary attribute (column) is not checked for uniqueness or references, only against its domain (allowed values).
Q7
Deleting a referenced EMPLOYEE also deletes the WORKS_ON tuples (rows) that refer to it. This option is called…
Cascade propagates the delete to the referencing tuples (rows).

C · The lecture’s exercise (Figure 5.6)

Suppose each operation is applied directly to the Figure 5.6 state. Discuss all integrity constraints violated by each operation, if any, and the different ways of enforcing these constraints. Write your answer, then open the model answer.

Q16
1. Insert ⟨'Robert', 'F', 'Scott', '943775543', '1972-06-21', '2365 Newcastle Rd, Bellaire, TX', M, 58000, '888665555', 1⟩ into EMPLOYEE.
MODEL ANSWERNo constraint is violated. Ssn 943775543 is new and not NULL, Super_ssn 888665555 (James Borg) exists, and Dno 1 (Headquarters) exists. The insert is accepted.
Q17
2. Insert ⟨'677678989', NULL, '40.0'⟩ into WORKS_ON.
MODEL ANSWERTwo violations. Entity integrity: Pno is part of the primary key (Essn, Pno) and is NULL. Referential integrity: Essn 677678989 does not exist in EMPLOYEE. Enforcement: reject the insert, or ask the user for a valid Pno and to insert employee 677678989 first (or correct the Essn).
Q18
3. Delete the WORKS_ON tuples (rows) with Essn = '333445555'.
MODEL ANSWERNo constraint is violated. No foreign key references WORKS_ON, so its four tuples (rows) for Franklin Wong (projects 2, 3, 10, 20) can be deleted.
Q19
4. Delete the PROJECT tuple (row) with Pname = 'ProductX'.
MODEL ANSWERReferential integrity is violated: ProductX is Pnumber 1, and WORKS_ON tuples (123456789, 1) and (453453453, 1) reference it. Enforcement: reject the delete; or cascade it, deleting those WORKS_ON tuples (rows); setting Pno to NULL is not possible because Pno is part of WORKS_ON’s primary key.
Q20
5. Modify the Super_ssn attribute (column) of the EMPLOYEE tuple (row) with Ssn = '999887777' to '908763451'.
MODEL ANSWERReferential integrity is violated: no employee has Ssn 908763451. Enforcement: reject the update; or first insert an employee with Ssn 908763451; or set Super_ssn to NULL (allowed, since it is not part of a key).
Q21
6. Modify the Hours attribute (column) of the WORKS_ON tuple (row) with Essn = '999887777' and Pno = 10 to '5.0'.
MODEL ANSWERNo constraint is violated. Hours is neither a key nor a foreign key, and 5.0 is a valid number of hours.
04

D · Order-processing database

CUSTOMER(Cust#, Cname, City) · ORDER(Order#, Odate, Cust#, Ord_amt) · ORDER_ITEM(Order#, Item#, Qty) · ITEM(Item#, Unit_price) · SHIPMENT(Order#, Warehouse#, Ship_date) · WAREHOUSE(Warehouse#, City). Ord_amt is the total amount of an order, Odate the date it was placed, Ship_date the date an order (or part of one) is shipped. An order can be shipped from several warehouses.

Q22
Give a primary key for each relation (table), stating any assumptions.
MODEL ANSWERCUSTOMER: Cust# · ORDER: Order# · ORDER_ITEM: (Order#, Item#), assuming an item appears once per order · ITEM: Item# · SHIPMENT: (Order#, Warehouse#), assuming one shipment per order per warehouse (add Ship_date to the key if a warehouse can ship the same order on several dates) · WAREHOUSE: Warehouse#.
Q23
Specify the foreign keys for this schema.
MODEL ANSWERORDER.Cust# → CUSTOMER.Cust# · ORDER_ITEM.Order# → ORDER.Order# · ORDER_ITEM.Item# → ITEM.Item# · SHIPMENT.Order# → ORDER.Order# · SHIPMENT.Warehouse# → WAREHOUSE.Warehouse#.
Q24
What other constraints can you think of for this database?
MODEL ANSWERExamples: Qty > 0; Unit_price > 0; Ord_amt ≥ 0 and equal to the sum of Qty × Unit_price over the order’s items; Ship_date ≥ Odate; ORDER.Cust# NOT NULL (every order belongs to a customer); Cname NOT NULL.
Q25
Which of these operations would be rejected, and why? (a) Delete a CUSTOMER who has orders. (b) Insert an ORDER_ITEM for an Item# that is not in ITEM. (c) Update a WAREHOUSE’s City.
MODEL ANSWER(a) Rejected (referential integrity: ORDER.Cust# still references the customer), unless the delete cascades. (b) Rejected (referential integrity: Item# refers to nothing). (c) Accepted: City is neither a key nor a foreign key.
