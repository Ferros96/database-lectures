    Domain constraints

    DEFINITION
    dom(A)

    Within each tuple, the value of each attribute A must be an atomic value from the domain dom(A).

    Keys

    Key constraints, candidate keys and the primary key

    Key constraints

    A relation is a set of tuples

    A relation is defined as a set of tuples.

    Tuples must be distinct

    No two tuples can have the same combination of values for all their attributes.

    Keys identify tuples

    The value of a key attribute can be used to identify uniquely each tuple in the relation.

    Time-invariant

    A key is determined from the meaning of the attributes; the property must continue to hold when we insert new tuples.

    NULL values constraint

    DEFINITION
    NOT NULL

    A constraint on attributes that specifies whether null values are or are not permitted.

    Example

    STUDENT.Name If every STUDENT tuple must have a valid, non-null value for Name, then Name of STUDENT is constrained to be NOT NULL.

    Relational database schema

    Many relations, related in various ways

    Relational database schema

    DEFINITION
    S = {R1, R2, …, Rm}

    A relational database usually contains many relations whose tuples are related in various ways. A relational database schema S is a set of relation schemas plus a set of integrity constraints IC.

    Its state

    Database state DB (instance) DB = {r1, r2, …, rm}: a set of relation states where each ri is a state of Ri.
    Must satisfy IC The relation states ri must satisfy the integrity constraints specified in IC.

    Integrity constraints

    Entity integrity, referential integrity and foreign keys

    Entity integrity constraint

    No NULL primary keys

    The entity integrity constraint states that no primary key value can be NULL.

    Why

    The primary key value is used to identify individual tuples in a relation.

    Otherwise

    Having NULL values for the primary key implies that we cannot identify some tuples.

    Referential integrity constraint

    DEFINITION
    Referential integrity

    Specified between two relations to keep their tuples consistent: a tuple in one relation that refers to another relation must refer to an existing tuple in that relation.

    Example

    EMPLOYEE.DNO → DEPARTMENT.DNUMBER DNO gives the department each employee works for, so its value in every EMPLOYEE tuple must match the DNUMBER value of some DEPARTMENT tuple.

    Foreign key (FK)

    DEFINITION
    FK of R1 → R2

    Referential integrity is based on the concept of a foreign key. A set of attributes FK in relation schema R1 is a foreign key of R1 that references R2 if it satisfies two rules.

    The two rules

    1. Same domain The attributes in FK have the same domain(s) as the primary key attributes PK of R2; FK is said to reference (refer to) R2.
    2. Exists or is NULL A value of FK in a tuple t1 of r1(R1) either occurs as a value of PK for some tuple t2 in r2(R2), or is null.
    Referential integrity constraints typically arise from the relationships among the entities represented by the relation schemas.

    Referential integrity on the COMPANY schema

    Each foreign key (left) must match an existing primary key value (right) or be NULL.

    Key takeaways

    1. 01

      Four kinds of constraints: domain, key, entity integrity and referential integrity.

    2. 02

      Every value must be atomic and come from its attribute’s domain dom(A).

    3. 03

      Keys identify tuples uniquely; one candidate key is chosen as the primary key (underlined).

    4. 04

      Entity integrity: no primary key value can be NULL.

    5. 05

      Referential integrity: a foreign key value must match an existing primary key value in the referenced relation, or be NULL.

    Q1What does a domain constraint require?

    Within each tuple, the value of each attribute A must be an atomic value from the domain dom(A).

    Q2Why shouldn’t Name be a key of STUDENT?

    Because there is no guarantee that two students with identical names will never exist, and a key must stay valid as new tuples are inserted.

    Q3What is the difference between a candidate key and the primary key?

    A relation can have several candidate keys (e.g. License_number and Engine_serial_number of CAR); the primary key is the one designated to identify tuples.

    Q4What does the entity integrity constraint state?

    No primary key value can be NULL, because the primary key identifies individual tuples.

    Q5Give the two rules for a foreign key FK of R1 referencing R2.

    1) FK has the same domain(s) as the primary key PK of R2. 2) Each FK value in r1(R1) either occurs as a PK value of some tuple in r2(R2) or is null.

    Q6In COMPANY, which attribute does EMPLOYEE.Dno reference?

    DEPARTMENT.Dnumber.
