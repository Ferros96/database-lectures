A · Concepts

Pick the best answer. You get feedback straight away.

Q1
Which constraint states that no primary key value can be NULL?
Entity integrity: the primary key identifies tuples, so it can never be NULL.
Q2
“Within each tuple, the value of each attribute A must be an atomic value from dom(A)” describes the…
That is the domain constraint.
Q3
A relation has two attributes that each identify every tuple uniquely. They are…
Each is a candidate key; one of them is designated the primary key.
Q4
By convention, the attributes of the primary key are…
Primary key attributes are underlined.
Q5
A foreign key value in a tuple must…
Rule 2 of a foreign key: it occurs as a PK value of some tuple in r2(R2), or is null.
Q6
A database state DB is valid only if…
The relation states ri must satisfy the integrity constraints specified in IC.
Q7
Why is Name not a key of STUDENT, even if all current names are different?
A key must be time-invariant: it must still hold when new tuples are inserted.

Q9
In the COMPANY schema, give the primary key of each relation.
MODEL ANSWEREMPLOYEE: Ssn · DEPARTMENT: Dnumber · DEPT_LOCATIONS: (Dnumber, Dlocation) · PROJECT: Pnumber · WORKS_ON: (Essn, Pno) · DEPENDENT: (Essn, Dependent_name).
Q10
List every foreign key in COMPANY that references EMPLOYEE.Ssn.
MODEL ANSWEREMPLOYEE.Super_ssn, DEPARTMENT.Mgr_ssn, WORKS_ON.Essn and DEPENDENT.Essn.
Q11
Which foreign keys reference DEPARTMENT.Dnumber?
MODEL ANSWEREMPLOYEE.Dno, DEPT_LOCATIONS.Dnumber and PROJECT.Dnum.
Q12
A foreign key may be NULL but a primary key may not. Explain why, using the rules from the lecture.
MODEL ANSWEREntity integrity says no primary key value can be NULL, because the primary key is used to identify individual tuples. A foreign key only refers to another tuple, and rule 2 allows its value to be null (the reference is simply missing or unknown).

Q13
Add EMPLOYEE ⟨Ahmed, Ali, NULL, 333445555, 4⟩
Ssn is the primary key and it is NULL, so entity integrity is violated.
Q14
Add EMPLOYEE ⟨Sara, Omar, 123456789, 888665555, 1⟩
Ssn 123456789 already belongs to John Smith. Two tuples would share a key value, so the key constraint is violated.
Q15
Add EMPLOYEE ⟨Lina, Saad, 444556666, 888665555, 7⟩
Dno 7 does not exist in DEPARTMENT.Dnumber, so referential integrity is violated.
Q16
Add EMPLOYEE ⟨Omar, Nasr, 555667777, NULL, 4⟩
The key is new and not NULL, Dno 4 exists, and the foreign key Super_ssn may be NULL. No constraint is violated.
Q17
Add EMPLOYEE ⟨Huda, Salem, 666778888, 999999999, 5⟩
Super_ssn references EMPLOYEE.Ssn, and no employee has Ssn 999999999, so referential integrity is violated.
Q18
Add DEPARTMENT ⟨Sales, six, 987654321⟩
Dnumber must be an integer from its domain; “six” is not, so the domain constraint is violated.
Q19
Add DEPARTMENT ⟨Finance, 2, 111111111⟩
Mgr_ssn references EMPLOYEE.Ssn, and there is no employee with Ssn 111111111, so referential integrity is violated.

Q20
INSERT into DEPARTMENT ⟨Sales, 5, 888665555⟩
Dnumber is the primary key of DEPARTMENT and 5 already belongs to Research, so the key constraint is violated.
Q21
INSERT into DEPARTMENT ⟨Sales, 6, NULL⟩
6 is a new, non-null key. Mgr_ssn is a foreign key and may be NULL (unless it was declared NOT NULL), so nothing is violated.
Q22
DELETE the DEPARTMENT tuple for Research (Dnumber 5)
John Smith and Franklin Wong have Dno = 5. After the delete their foreign key would point to a department that no longer exists.
Q23
DELETE the EMPLOYEE tuple for John Smith (Ssn 123456789)
No tuple references Ssn 123456789 (it is nobody’s Super_ssn or Mgr_ssn), so the delete is safe.
Q24
DELETE the EMPLOYEE tuple for Franklin Wong (Ssn 333445555)
John Smith’s Super_ssn and Research’s Mgr_ssn both reference 333445555. Deleting Franklin breaks those references.
Q25
UPDATE John Smith: set Dno = 1
Department 1 (Headquarters) exists, so the foreign key is still valid.
Q26
UPDATE John Smith: set Dno = 9
There is no Dnumber 9 in DEPARTMENT, so the new foreign key value has nothing to refer to.
Q27
UPDATE Jennifer Wallace: set Ssn = 123456789
123456789 is already John Smith’s Ssn. Two tuples would share the same primary key value.
Q28
UPDATE James Borg: set Ssn = NULL
A primary key can never be NULL (entity integrity). It would also break the Super_ssn and Mgr_ssn references to 888665555.
Q29
UPDATE Headquarters: set Dnumber = 'one'
Dnumber is an integer; the string 'one' is not in its domain.

E · Design and fix

Practical questions. Write your answer first, then open the model answer.

Q30
Write one EMPLOYEE tuple that violates two different constraints at the same time, and name both.
MODEL ANSWERExample: ⟨Ali, Hassan, NULL, 333445555, 7⟩. Ssn is NULL, which breaks entity integrity, and Dno 7 does not exist in DEPARTMENT, which breaks referential integrity.
Q31
Deleting the Research department is rejected because employees still reference it. What could be done first so the delete becomes valid?
MODEL ANSWERRemove or change the references first: move John Smith and Franklin Wong to an existing department (for example set Dno = 4), or set their Dno to NULL if that is allowed. The DBMS can also be told to do this automatically, which you will meet later with SQL (ON DELETE SET NULL / CASCADE).
Q32
A university stores STUDENT(Student_id, Name, Email, Major), COURSE(Course_no, Title, Credits) and ENROLL(Student_id, Course_no, Semester, Grade). (a) Give the primary key of each relation. (b) Which attribute of STUDENT is also a candidate key? (c) List the foreign keys.
MODEL ANSWER(a) STUDENT: Student_id · COURSE: Course_no · ENROLL: (Student_id, Course_no, Semester), since a student can take the same course again in another semester. (b) Email, because no two students share an email address. (c) ENROLL.Student_id → STUDENT.Student_id and ENROLL.Course_no → COURSE.Course_no.
Q33
For the same university database, give one NOT NULL constraint and one domain constraint that make sense, and say why.
MODEL ANSWERNOT NULL: STUDENT.Name, because every student must have a name. Domain: COURSE.Credits must be an integer between 1 and 6 (or Grade must be one of A, B, C, D, F).
Q34
Can ENROLL.Student_id be NULL? Explain using both entity integrity and the foreign key rules.
MODEL ANSWERNo. As a foreign key alone it could be NULL (rule 2), but Student_id is also part of ENROLL’s primary key, and entity integrity says no primary key value can be NULL.
