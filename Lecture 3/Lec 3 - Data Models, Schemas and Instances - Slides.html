Data abstraction and data models

DEFINITION
Data abstraction

Suppressing details of data organization and storage, and highlighting the essential features for an improved understanding of data, so different users can perceive data at their preferred level of detail.

Key definitions

Data model A collection of concepts that can be used to describe the structure of a database. Most also include basic operations for retrievals and updates.
Structure of a database The data types, relationships and constraints that apply to the data.

01 · Data models

Categories of data models

Data models are categorized by the types of concepts they use to describe the database structure.

users’ viewcomputer storage
Closest to users

High-level (conceptual)

Concepts close to the way many users perceive data.

In between

Representational (implementation)

Easily understood by end users, but not too far from how data is organized in storage. Hides many storage details, yet can be implemented directly.

Closest to storage

Low-level (physical)

Describe the details of how data is stored on computer storage media, typically magnetic disks. Meant for computer specialists.

01 · Data models

Object data model

The rise of object-oriented programming in the 1980s, and the need to store and share complex structured objects, led to object-oriented databases (OODBs), first seen as a competitor to relational databases.

Objects

Defines a database in terms of objects, their properties and their operations.

Classes

Objects with the same structure and behavior belong to a class; classes are organized into hierarchies.

Methods

Operations of each class are specified as predefined procedures called methods.

Object-relational systems

Relational DBMSs that extended their models with object database concepts.

62153 · Intro to Database Systems · Lecture 313 / 26
01 · Data models

XML model and physical data models

XML model

A standard for exchanging data over the Web and a basis for native XML systems. Uses hierarchical tree structures and combines database concepts with document representation. Data are elements; tags nest data into complex hierarchies. Many commercial DBMSs have added XML capabilities.

Physical data models

Describe how data is stored as files in the computer: record formats, record orderings and access paths. An access path is a search structure that makes finding particular records efficient, such as indexing or hashing.

02 · Schemas, instances and database state

Schema vs database state

Database schema

  • The description of the database
  • Specified during database design
  • Not expected to change frequently
  • Displayed as a schema diagram; each object (STUDENT, COURSE) is a schema construct
vs

Database state (snapshot)

  • The actual data in the database at a particular moment
  • Also called the current set of occurrences or instances
  • Changes frequently: every insert, delete or modification creates a new state
  • Many states can correspond to one schema

02 · Schemas, instances and database state

From schema to current state

1

Define the schema

When we define a new database, we specify only its schema to the DBMS.

2

Empty state

At that point the database state is empty, with no data.

3

Initial state

Reached when the database is first populated or loaded with data.

4

Current state

Every update produces another state; at any time the database has a current state.

The DBMS stores the schema constructs and constraints (meta-data) in the DBMS catalog.

03 · Three-schema architecture

The three-schema architecture

  1. 1
    Proposed to achieve the characteristics of the database approach.
  2. 2
    Goal: separate the applications from the physical database, hiding how data is organized from users.
  3. 3
    Most DBMSs do not separate the three levels completely, but support the architecture to some extent.
62153 · Intro to Database Systems · Lecture 320 / 26
03 · Three-schema architecture

The three levels

External (view) level

Many external schemas or user views. Each describes the part of the database one user group cares about and hides the rest. Usually implemented with a representational data model.

Conceptual level

One conceptual schema describing the whole database for a community of users: entities, data types, relationships, user operations and constraints, hiding physical storage details.

Internal level

An internal schema describing how data is actually stored and accessed, using a physical data model with complete storage details and access paths.

04 · Languages and classification

Database languages

Two sub-languages form the standard for most popular databases.

DDL: Data Definition Language

  • Defines the conceptual and internal schemas
  • Not procedural: describes types of entities and relationships in terms of a data model
vs

DML: Data Manipulation Language

  • Manipulates the database
  • Retrieval, insertion, deletion and modification of data

Key takeaways

  1. 01

    A data model describes a database’s structure: its data types, relationships and constraints.

  2. 02

    Models range from high-level (ER) to representational (relational, network, hierarchical) to physical.

  3. 03

    The schema describes the database; the state is the data at a moment in time.

  4. 04

    The three-schema architecture separates external views, the conceptual schema and internal storage.

  5. 05

    DDL defines schemas; DML retrieves, inserts, deletes and modifies data.
