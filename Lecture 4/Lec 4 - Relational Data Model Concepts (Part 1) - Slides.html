01 · From tables to relations

The relational model in one idea

DEFINITION

The relational model represents the database as a collection of relations. Each relation looks like a table of values.

In plain words

A relation is basically a table. A relational database is just a set of tables, like the five tables of the University database.

Example: the University database is 5 relations
STUDENTone row per student
COURSEone row per course
SECTIONone row per course section
GRADE_REPORTone row per grade a student received
PREREQUISITEone row per course–prerequisite pair

Keep it simple: relation means table. Everything we built in the University example is already a relational database. Each table is one relation.

01 · From tables to relations

Relation schema (table heading): the heading of the table

DEFINITION

A relation schema R(A1, A2, …, An) is made up of a relation name R and a list of attributes (columns) A1, A2, …, An.

In plain words

The schema describes the table: its name and its column names. It does not contain any data. Think of it as the empty table heading.

Example: the STUDENT schema
STUDENT (Name, SSN, HomePhone, Address, Office_Phone, Age, GPA)
R = STUDENTA1 = NameA2 = SSN… A7 = GPA

Write R(A1, …, An) on the board, then fill it in with STUDENT. Stress that the schema is the description, not the data. The data comes later, as the relation state.

Degree (number of columns): count the attributes (columns)

n =
7

attributes = degree 7

The degree of a relation is the number of attributes n of its relation schema (table heading). Count the columns, never the rows.

Relation schema of degree 7
STUDENT (Name, SSN, HomePhone, Address, Office_Phone, Age, GPA)
Sometimes written with data types
STUDENT (Name: string, SSN: string, HomePhone: string, Address: string, Office_Phone: string, Age: integer, GPA: real)

Degree is a common exam question. Count with the class: seven attributes, degree seven. Inserting more students adds tuples but never changes the degree. The second form shows the same schema with a data type for each attribute.

Domain (allowed values): the allowed values of a column

DEFINITION

A domain D is a set of atomic values. A data type or format is also specified for each domain.

In plain words

A domain is the list of values a column may hold. Atomic means each value is one single, indivisible value, never a list.

Examples from the lecture
Phone_numbers7-digit numbers valid in an area code; format ddd-dddd (d = decimal digit)
Grade_point_averagesreal numbers between 0 and 4
Employee_agesvalues between 15 and 80
Social_security_numbersthe valid 9-digit SSNs

A domain has two parts: the meaning (what values make sense) and the data type or format. Phone_numbers is a good example of a format: a character string of the form ddd-dddd.

01 · From tables to relations

Relation state (the rows stored now): the data at one moment

DEFINITION

A relation state r of the relation schema (table heading) R(A1, A2, …, An), denoted r(R), is a set of n-tuples (rows) r = {t1, t2, …, tm}.

In plain words

The state is the rows stored in the table right now. Each tuple holds n values, one for each attribute (column). The state changes whenever data is added, changed or removed.

Example: part of r(STUDENT)

Connect this to Lecture 3: schema versus state. The schema R is the heading; the state r(R) is the set of tuples. Here each tuple has seven values because the degree is seven.

Ordering of tuples (rows) is not important

A relation is defined as a set of tuples.
Tuples in a relation do not have any particular order.

02 · Characteristics of relations

Atomic values only

DEFINITION

Each value in a tuple (row) is an atomic value. Composite and multi-valued attributes (columns) are not allowed.

In plain words

One cell holds one value. You cannot store a list or a value with inner parts in a single cell.

How the relational model handles them
✗ Not allowed in a cell
  • Composite attributes
  • Multi-valued attributes
✓ Represented instead by
  • Only their simple component attributes
  • A separate relation (table)

Example to say out loud: if a student had two home phones, we could not put both in HomePhone. We would need a separate relation for phone numbers. A composite attribute like an address is stored as its simple parts.

Quick check

QUICK CHECK

A student has two home phone numbers. How should the relational model store them?

A

Both numbers in one HomePhone cell, separated by a comma

B

Add HomePhone2, HomePhone3, … columns forever

C

In a separate relation, because multi-valued attributes are not allowed

D

Store only one number and set the other to NULL

C. Each value in a tuple (row) must be atomic. Multi-valued attributes (columns) must be represented by separate relations (tables).

Option A breaks atomicity. Option D loses data. The lecture’s rule is option C.

Key takeaways

  1. 01

    The relational model represents a database as a collection of relations (tables).

  2. 02

    Tuple = row, attribute = column header, relation = table, domain (allowed values) = set of allowed atomic values.

  3. 03

    A relation schema (table heading) R(A1, …, An) has degree (number of columns) n; a relation state (the rows stored now) r(R) is a set of n-tuples (rows).

  4. 04

    Tuple order does not matter; values are atomic and may be NULL when unknown.
